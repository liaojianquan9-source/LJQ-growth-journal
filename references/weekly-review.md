# 周报 / 周复盘

触发：用户说「写周报」「总结这周」「周复盘」等。

## 素材收集

- 路径 A：**先读库根目录的 `index.md` 目录**，定位本周（或用户指定周）的日记条目，再按需读取这些日记全文，连同上周周报（若存在）。
- 路径 B：请用户粘贴本周日记内容，或引导用户口头回顾（用下方提问清单）。

## 引导提问（素材不足时使用）

1. 本周计划的事，达成了吗？为什么达成 / 未达成？
2. 本周最大的一个进展是什么？
3. 哪个问题这周出现了不止一次？
4. 哪些事应该继续做？停止做？开始做？

## 起草规则（KISS 模型）

按 `assets/templates/weekly.md` 起草：

- **本周概览（先于一切）**：本周事件的目录级总览——**只陈述发生了什么，不写经过、结果或评价**（评述由下方 KISS 区块承接）；不加小标题、不限条数；相同或相关的内容合并为一条；**每条句尾加日期标签**（格式 `#MMDD`，如 `#0731`），便于溯源到具体日记。条目统一用**引用块编号列表**（`> 1. …`）；**模板与成品中不写任何说明文字**——「本周概览」标题本身即是说明，起草规则只留在本文件，绝不写进输出。年度总结将直接引用全部周报的概览，不再逐篇读日记。
- **Keep（保持）**：本周做得好、值得继续的**具体做法**。拒绝「状态不错」式泛泛结论——每条必须是可以复用的行为。
- **Improve（改进）**：做得不好、需要调整的地方，附改进动作。
- **Start（开始）**：要启动的新行动。每条满足：具体做什么 + 什么时候做。
- **Stop（停止）**：要停掉的事。
- **反复出现的问题（错题集）**：扫描本周全部日记的「想法」与 `#difficult` 标签，列出出现 ≥2 次的问题，注明各出现在哪天。这是周报最有价值的部分，直接呈现，不评判（观察模式开启时可加一句点评）。
- **行动项对账**：上周周报 Start 项与本周日记「行动」块的完成情况。

## 确认与落盘

同日记流程：陈列 → 用户确认/修改 → 路径 A 写入 `weekly/成长记录-第XX周-YYMMDD-YYMMDD.md`（周一起、周日止；周数为开始记录以来的第几周，与日记「第N天」同套计数，如 `weekly/成长记录-第03周-260622-260628.md`），路径 B 输出纯净 Markdown（一行文件名 + 一个代码块，零赘述）。

周报同时是 AI 的导航文件：保持 frontmatter 完整（`type: weekly`、`week`、`tags` 汇总本周日记标签）。
