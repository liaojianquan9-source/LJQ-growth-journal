# 决策日志（可选模块）

触发：用户说「记录一个决策」「今天做了个重要决定」，或对话中出现重大决策信号（换工作、大额支出、重要关系决定等）时主动询问一次「要不要把这段决策记下来？」用户拒绝则不记。

## 记录规则

按 `assets/templates/decision.md` 引导用户回答：

1. **决策**：一句话说清决定了什么
2. **选项**：当时有哪几个选项（2-5 个），各是什么
3. **理由**：为什么这么选——**真实记录当时的情绪、信息和偏见，不美化**。大脑会事后用结果改写记忆，这段文字的价值就在于「当时怎么想」
4. **信心**：0-100%
5. **预期结果**：尽量可量化，「成功」长什么样
6. **回检日期（revisit）**：1 周 / 1 个月 / 3 个月后，由用户选

## 存放方式

- 写入当天日记的 frontmatter：`decision: true`、`revisit: YYYY-MM-DD`，正文附决策块；或单独存 `decisions/YYYY-MM-DD-<决策名>.md`（用户库结构支持时）。

## 回检机制（复利的核心环节，仅路径 A）

- 每次开始记录时，扫描历史日记 frontmatter 中 `revisit` 已到期的决策。
- 有到期决策时，在开场后主动提出：「X 月 X 日你记录了决策 XX，定的回检日期到了——实际发生了什么？你还会做同样的决定吗？」
- 回检结果追加到原决策记录：实际结果 + 「还会做同样的决定吗」+ 一句经验教训（标 `#教训`）。
